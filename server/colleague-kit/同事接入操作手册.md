## 二、方式一：浏览器图形界面（推荐，最省事）

### 打开地址

```
http://192.168.0.44:7789
```

浏览器里会出现一个数据库浏览器，界面长这样：

- **左侧**：表目录，按「主体与组织 / 交易与收益 / 名额与配额 / 商品与内容 / 账务与运营」分组
- **中间**：点击表名后，可切 4 个页签 —— **数据**（分页看真实数据）、**结构**（字段类型和中文说明）、**关系**（外键）、**SQL**（写 SQL）
- **鼠标悬停**字段名，会弹出该字段的中文说明

### 写入数据

1. 左侧点一张表
2. 点 **SQL** 页签
3. 下方会出现「数据写入」区域，写好 SQL 后点「执行写入」
4. 浏览器会弹确认框，确认后执行；执行完左侧「数据」页自动刷新

> **表格名前面有「托管」小标签的，点写入按钮会直接被拒绝** —— 这是保护机制，不是故障，理由见第四节。

### 写入的硬性约束

| 约束 | 说明 |
|---|---|
| 只允许 4 种语句 | `INSERT` / `UPDATE` / `DELETE` / `REPLACE` |
| `UPDATE`、`DELETE` 必须带 `WHERE` | 不带 `WHERE` 会被拒绝，防止误清空整表 |
| 不能改表结构 | `DROP` / `TRUNCATE` / `ALTER` / `CREATE` 一律拒绝（数据库层也挡着） |
| 不能写多语句 | 一条一次执行，防止 `;` 拼接绕过检查 |
| 不能操作别的库 | 只能操作 `naoshang` 库 |

## 三、方式二：命令行客户端

### 连接命令

```bash
mysql -h 192.168.0.44 -P 3307 -u colleague -p naoshang
```

回车后提示 `Enter password:`，输入密码（见第八节），再回车即进入。

> **注意**：端口是 **3307**，不是默认的 3306。

### 常用操作

```sql
-- 看有哪些表
SHOW TABLES;

-- 看某张表的结构
DESC `support_feedback`;

-- 查数据
SELECT * FROM `payments` LIMIT 20;

-- 写入一行（support_feedback 是可写表）
INSERT INTO `support_feedback` (`id`,`content`,`created_at`)
VALUES ('demo_001','测试内容','2026-01-01 00:00:00');

-- 改数据（务必带 WHERE）
UPDATE `support_feedback` SET `content`='改过的内容' WHERE `id`='demo_001';

-- 删数据（务必带 WHERE）
DELETE FROM `support_feedback` WHERE `id`='demo_001';

-- 退出
exit;
```

### 验证连接成功

连接后执行：

```sql
SELECT CURRENT_USER();
```

正常应返回 `colleague@192.168.%`，说明是以受限账号连进来的。

## 四、⚠️ 托管表：为什么有些表不让写

### 现象

左侧表目录里，带「托管」标签的表，点写入会被拒绝，提示：

> 「xxx」是托管表（由 db.json 单向镜像生成），直写会在 **db.json 下次变更触发同步时**被整表覆盖（不是每秒覆盖，而是业务一旦改动 db.json 才会触发）。

### 原因

脑商AI 的数据库**不是真正的数据源**，而是一份**镜像**：

```
业务真源 db.json  ──同步器(db.json 变更才触发)──►  MySQL(仅供查看)
                                                    ▲
                                       同事直写的数据 → 下次 db.json 变更触发同步时被覆盖（几秒到数天不等）
```

同步器刷新托管表时，执行的是 `DELETE FROM 表` + 整表重建。**不是更新，是删除后重写**。所以你写进去的数据会被同步器抹掉，且无法找回。

### 结论

| 需求 | 怎么做 |
|---|---|
| 只想**看**托管表的数据 | ✅ 随便看，不受限 |
| 想**写**托管表（users / orders / commissions 等业务数据） | ❌ 不能直写。请让库机管理员通过业务接口写入 |
| 想写**测试数据 / 临时数据** | ✅ 写非托管表（见下表 7 张） |

### 托管表清单（38 张，**禁止直写**）

```
activation_codes    activity_prices    allocation_quotes   allocations
applications        assets             co_store_owners     co_stores
coaches             columns            commissions         counters
coupons             entitlement_orders  experience_ledger  free_upgrade_log
invite_codes        jobs               learning_progress   members
orders              password_resets    payments            promotion_tasks
quota_activity_batches  quota_ledger  quota_transactions  quotes
regional_agents     skus               stock_ledger        store_transfers
training_feedback   upline_history     users               wechat_tickets
withdrawals
```

### 可写表清单（7 张，同步器不碰，**可安全直写**）

```
addresses           app_settings       material_renders    pay_accounts
settings            settlements          support_feedback
```

> 表的中文说明见同目录 `table-classification.json`。
>
> **为什么可写表这么少**：只要一张表会被 `db.json → MySQL` 同步器管辖，它就必须在**任何时刻**都禁写。
> 因为同步器是常驻的 —— 哪怕此刻该表是空的，只要之后业务产生了这批数据，
> 同步器就会 `DELETE FROM` 整表重建，把同事刚写进去的内容一并抹掉。
> 所以判定用的是「系统**声明**会写哪些表」（扫 mapping.js 源码），而不是「此刻哪些表有数据」。
> 这套判定对 db.json 的任何状态都恒定不变（38/7），不存在时序漏洞。
>
> ⚠️ **重要**：即便写在「可写表」，数据也**不会进入业务真源 db.json**，后端 API / 前端一律读不到。
> 可写表只适合放与业务无关的临时 / 测试数据；若想让系统真正识别你写入的内容，仍须走业务接口（API），而非直连 MySQL。

## 五、方式三：Navicat / DBeaver 等图形工具

新建连接时填这几个参数：

| 字段 | 值 |
|---|---|
| 主机 / Host | `192.168.0.44` |
| 端口 / Port | `3307` |
| 用户名 / User | `colleague` |
| 密码 / Password | 见第八节 |
| 数据库 / Database | `naoshang` |

### 两个常见报错

**① `Access denied for user 'colleague'@'xxx'`**
→ 口令输错了。注意区分大小写，密码里有特殊字符。

**② `Authentication plugin 'caching_sha2_password' cannot be loaded`**
→ 客户端版本太老。MySQL 8.4 默认用 `caching_sha2_password` 认证。
→ 解决：升级客户端（Navicat 12+ / DBeaver 21+ / MySQL Workbench 8.0.30+），或改用第二节的浏览器方式。

**③ 连接超时**
→ 检查是否和库机在同一局域网（同一网段）；或本机防火墙拦截。

## 六、方式四：脚本连库（Node.js / Python）

### Node.js（mysql2）

```js
const mysql = require('mysql2/promise');

(async () => {
  const conn = await mysql.createConnection({
    host: '192.168.0.44',
    port: 3307,
    user: 'colleague',
    password: process.env.DB_PASSWORD,   // 别把密码写死在代码里
    database: 'naoshang',
  });

  // 写
  await conn.query(
    'INSERT INTO `support_feedback` (`id`,`content`,`created_at`) VALUES (?,?,?)',
    ['demo_001', '测试内容', '2026-01-01 00:00:00']
  );

  // 读
  const [rows] = await conn.query('SELECT * FROM `payments` LIMIT 10');
  console.log(rows);

  await conn.end();
})();
```

### Python（PyMySQL）

```python
import os, pymysql

conn = pymysql.connect(
    host='192.168.0.44',
    port=3307,
    user='colleague',
    password=os.environ['DB_PASSWORD'],
    database='naoshang',
)

with conn.cursor() as cur:
    cur.execute("INSERT INTO support_feedback (id,content,created_at) VALUES (%s,%s,%s)",
                ('demo_001','测试内容','2026-01-01 00:00:00'))
    conn.commit()

    cur.execute("SELECT * FROM payments LIMIT 10")
    print(cur.fetchall())

conn.close()
```

### 脚本连库的额外限制

命令行用的 `colleague` 账号**权限更严**：不能 `DROP` / `TRUNCATE` / `ALTER` / `CREATE`。
需要改表结构时，找库机管理员处理。

## 七、常见问题排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 浏览器打不开页面 | 电脑不在同一网段 / 防火墙 | 确认和库机同网段；ping 192.168.0.44 |
| 页面能开但表都是空的 | 连错库 | 检查地址栏端口是 **7789** |
| `1045 Access denied` | 账号或密码错 | 核对第八节 |
| `2003 Can't connect` | 端口写成了 3306 | 改成 **3307** |
| 写入被拒：托管表 | 见第四节 | 换一张非托管表 |
| 写入被拒：必须带 WHERE | 防误删保护 | 补上 `WHERE 条件` |
| 写入后数据又没了 | 写的是托管表（确切时机：db.json 下次被业务改动触发同步时） | 同上，改写非托管表；若要让系统识别，走业务接口 |
| `caching_sha2_password cannot be loaded` | 客户端太老 | 升级客户端，或用浏览器 |
