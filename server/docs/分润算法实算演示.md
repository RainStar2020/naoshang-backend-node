## 2. 四笔交易逐笔实算（T1–T4）

### T1 戊（新用户）经丁（VIP）买「VIP整包」9,980 元 —— 合伙人渠道

- 消耗名额 need = 1−0 = 1；实付 = 零售价 9,980
- 丁（卖家）拿货成本 = 1 × 7,980 = 7,980 → **差价 9,980 − 7,980 = 2,000 归丁**
- 供货链级差（沿丁的上级链逐层）：

| 层级  | 计算                        | 归属 |
| --- | ------------------------- | -- |
| 丁→丙 | (7,980 − 7,500) × 1 = 480 | 丙  |
| 丙→乙 | (7,500 − 6,980) × 1 = 520 | 乙  |
| 乙→甲 | (6,980 − 6,500) × 1 = 480 | 甲  |

- 平级奖：链上无人同买家新档（VIP）→ 0
- 总部费 = 3,500×1 + 3,000×1 = 6,500（非门店老板售出，无门店服务费）
- **闭环：2,000+480+520+480+6,500 = 9,980 ✅ 分文不差**
- 丁名额 50→49；戊升 VIP，编号 → VIP0005

### T2 丙（天使）向乙（私董）批发补货 3 个「天使名额」，7,500/个，共 22,500 元 —— 批发补货（级联到总部）

> **购买流程**（用户 2026-10-24 口述）：下级找上级买 → 上级找自己的上级买 → … → 直到链顶向总部买；  
> 钱沿链向上逐层拆分；名额由总部逐层发放到买方的上级，最终到买方手里（升级则是买方的上级**消耗自己购买的名额**给买方升档，买方不入账）。

- need = 3；实付 = 7,500 × 3 = 22,500（买方按自己档位拿货价付费）
- 乙拿货成本 = 3 × 6,980 = 20,940 → **差价 22,500 − 20,940 = 1,560 归乙**
- 供货链级差：乙的上级甲（联创）(6,980 − 6,500) × 3 = **1,440 归甲**（链顶向总部拿货，终端价 = 总部底价 6,500/名额）
- 平级奖：链上无人与买家同档 → 0；乙非门店老板 → 门店服务费 0
- **闭环：1,560（乙）+ 1,440（甲）+ 19,500（总部 6,500×3）= 22,500 ✅**
- 名额：乙 200→197（扣库存）；丙 100→**103**（补货入账，可转售）

### T3 癸（新用户）经己（门店老板·D1）买「VIP整包」9,980 元 —— 门店渠道

- need = 1；实付 9,980；己拿货成本 = 1 × 7,500 = 7,500 → **差价 2,480 归己**
- 供货链级差：己→丙 (7,500−7,500)×1 = 0；丙→乙 520；乙→甲 480
- 平级奖 0；**门店服务费 = 3,000×1 = 3,000**（月度拆：门店 2,400→己、县区 300→辛、市 200→甲、省 100→甲，省/市代由联创甲兼任）；总部费 3,500
- **闭环：2,480+0+520+480+3,500+3,000 = 9,980 ✅**
- 己名额 100→99；癸升 VIP → VIP0009

### T4 亥（新用户）经辰（天使）买「天使整包」29,800 元 —— 同级链触发平级奖

- need = 3；实付 29,800；辰拿货成本 = 3 × 7,500 = 22,500 → **差价 7,300 归辰**
- 供货链级差：辰→丙 (7,500−7,500)×3 = 0；丙→乙 (7,500−6,980)×3 = 1,560；乙→甲 (6,980−6,500)×3 = 1,440
- **平级奖（2026-10-24 拍板：从供货上级级差扣，非额外出账）**：丙与辰同级（均为天使，拿货价 7,500→丙本跳吃不到差价）→ 丙拿平级奖，金额 = 其供货上级乙的拿货价 6,980×2%×3 = **418.8 归丙**；该 418.8 **从乙的级差中扣**（乙实发 1,560−418.8 = 1,141.2），不再由总部额外吸收。
- 总部费 19,500
- **闭环：7,300+0+(1,560−418.8)+1,440+19,500 = 29,800 ✅**（平级奖已内含于乙级差再分配，总分发与实付完全一致）
- 辰名额 50→47；亥升天使 → TS0010

## 4. 诊断单 T5：戊（VIP）经丁升级「天使」—— 已按用户 2026-10-24 拍板落地 ✅

**用户规则**：升级只付「目标档一口价 − 已付原档一口价」的差价，不为已有名额重复付费；升级流程同补货级联（上级逐级向总部买增量名额，上级消耗增量名额给买方升档）。

- 戊已付 VIP 9,980，天使一口价 29,800 → **戊实付差价 = 29,800 − 9,980 = 19,820**
- need = 升级增量 3−1 = **2**（只补 2 个名额）；丁（VIP）向上级链购 2 个名额、消耗这 2 个名额把戊升为天使
- 丁直接差价 = 19,820 − 2×7,980（丁拿货成本）= **3,860**
- 链上级差（按 2 名额）：(7,980−7,500)×2=960→丙；(7,500−6,980)×2=1,040→乙；(6,980−6,500)×2=960→甲
- **平级奖**：本单丙（天使，拿货价 7,500）与丁（VIP，拿货价 7,980）**不同档** → 丙本跳吃得到差价（960），**不触发平级奖**（2026-10-24 拍板修正：旧模型误用买家新档「天使」判定丙同级，多算 279.2 额外出账，已废）。
- 总部费 = 3,500×2+3,000×2 = 13,000
- **闭环：3,860+960+1,040+960+13,000 = 19,820 vs 实付 19,820 → ✅ 分文不差**（无额外平级奖，全部由订单额内闭环承担）

> 旧版（A）曾按整包零售价 29,800 收费、但只按 2 名额分账，缺口 7,980。已废弃，改按升级差价计费（即本方案 C）。`commission.js` 的 `UPGRADE_DIFF` 表：VIP→天使 **19,820**、天使→私董 30,000、私董→联创 180,000。

## 6. 本次实算发现并已修复的问题

1. **下单升档后对外编号不刷新**（已修）：`createOrder` 改买家档位后未重算 display_id，导致戊买了 VIP 仍显示 YH0005。已在 `routes.js` 补 `IZ.recomputeDisplayId(db, buyerId)`，与 `updatePartner` 同口径。修复后：戊→VIP0005→TS0005、癸→VIP0009、亥→TS0010。
2. **多名额补货「拿货成本」字段记错**（已修）：rawQuota≠整包名额数时，sellerCost 只记 1 个包的成本（补 5 个 VIP 名额记 6,500，应为 32,500），公式文案「实付−成本=差价」对不上。已改为 `need × 卖家档价`；差价金额本身一直是对的，此为账目标签修复。
3. **平级奖判定旧 bug（已修）**：旧模型用「买家套餐档位」做同级判定，会漏掉「卖家上级与卖家同级」这一类平级奖（如 T3：己天使卖新用户、其上级丙天使同级 → 丙本跳吃不到差价）。新模型改为沿「买家→卖家→卖家上级链」逐跳用**实际拿货价**判定同级，并已将平级奖资金来源从「额外出账/总部吸收」改为「从供货上级级差中扣」（用户 2026-10-24 拍板）。详见 §4 与 §7 #2。
