## 二、技术费与两笔提成（任命即时落账）

用户口径：「直推提成只算技术费，但交的费用算合计」。  
例：联创直推一人成为单店代理 → 直推奖 = **4w × 15% = 6000**（不是 8w × 15%）。

| 提成    | 公式                                                     | 说明                       |
| ----- | ------------------------------------------------------ | ------------------------ |
| 直推代理奖 | 新代理**技术费** × 推荐人**合伙人身份**直推比例（VIP5%/天使10%/私董15%/联创15%） | 与合伙人体系 `DIRECT_RATIO` 同表 |
| 业务提成  | 新代理**技术费** × 开发人**代理身份**业务提点（省20%/市18%/区县15%/单店15%）    | 取 `AGENT_SHARE.bBiz`     |

- **两笔都发**，收件人都是开发人（推荐人），分别按两种身份计算；开发人缺少对应身份时该项不发。
- 落账：`agdirect-{agentId}` / `agbiz-{agentId}`，type=`agent`，subtype 区分，幂等（同 id 覆盖）。
- 无开发人 → 不落账；开发人=本人 / 不存在 → 抛错。

## 三、代理固定上级链（无跨级）

```
单店代理 → 区县代 → 市代 → 省代 → 总部     （逐级固定，不存在跨级）
```

实物拿货差价沿固定链结算（`productSplit.agentChainTierDiff`）：  
每级赚「下一级折扣 − 本级折扣」× 基准价；链底卖方赚「买方折扣 − 卖方折扣」× 基准价；总部收 省代折扣 × 基准价。

算例（VIP 向单店代理买脑商Pad 6980）：门店 2094 + 区县 698 + 市代 349 + 省代 349 + 总部 2094 = **5584 = 6980×0.8** ✓

## 十、产品订单链路（v1.1 新增）

入口：`POST /api/order/product`（用户路由块，admin 可经 `?userId=` 覆盖买家）→ `routes.createProductOrder(db, input)`。

```
产品购买 → 成交价（档位折扣）→ 按 kind 落账分润 → 合伙人产品提成 → 幂等佣金
```

**流程**：

1. **成交价**：买方档位优先取**代理记录**（代理本人按代理折扣，见 A9）→ 合伙人档位 → `list` 原价；`paid = 固定成本 + 变动成本 × 档位折扣`。⚠️ **特色产品例外**：代理买家按「对应合伙人档位」计价（省代→联创 / 市代→私董 / 区县代→天使 / 单店→VIP，见 `productSplit.featuredLevelFor`），不享受代理折扣。
2. **可分池 pool = paid − 固定成本**（fixedCost=0 时等于实付，与旧「实付×比例」口径一致）。
3. **合伙人产品提成**：基数=pool，按上级合伙人身份 5/10/15/15%，`uplineProductCommission` 落账。
4. **按 kind 分润**（佣金 id `po-{orderId}-{role}`，type=`product`，subtype=角色，幂等）：

| kind     | 落账规则                                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| physical | `agentChainTierDiff` 沿固定链结算级差；**提成从链底卖方行扣**，溢出部分由总部行承担（A7）；`fixedTotal>0` 另加 `fixed_cost` 行归 HQ；无卖方（省代买家）走 `chain_hq_direct`             |
| featured | `netPool = pool − 提成`；`featuredSplit(netPool + fixedTotal)` 8 个分成行；门店交付时巡查行 `status='pending_allocation'`（权归区县负责人），总部交付时门店交付/区县巡查两行收归 HQ |
| software | `virtualDeliverySplit(netPool, deliveryType)` 四行（hq/province/city/store）                                                                 |
| virtual  | 同上                                                                                                                                       |
| admin    | `adminFeeSplitDetail(paid)`：总部 5% / 销售门店 5%（ownStore→区域单店代理）/ 上课团队 90%（HQ 待内部结算）；无折扣、无产品提成                                               |

1. **幂等**：落账前先按 orderId 删除旧订单与旧佣金；同 orderId 重放订单与佣金金额一致。
2. **区域匹配**：`agentsByLevel` 按 `regionCode` 匹配，缺失档位视为空位归 HQ（与结算链路约定一致）。
3. 返回 `{order_id, paid, fixedTotal, pool, partnerCommission, rows, byRecipient, total, closure}`。

**算例**（VIP p4 向 D1 区（区县代 p5+单店 p6）买脑商Pad 1 台）：

```
paid 5584 → 提成 558.4（p3 天使 10%）
链底门店 1535.6（=2094−558.4 提成扣减）→ 区县 698 → 市代 349(HQ) → 省代 349(HQ) → 总部 2094
6 笔佣金、total=5584、closure=true
```

**H5**：用户端「产品」tab（`loadUserProduct`）拉 `/api/products` + 逐产品到手价，特色产品带交付类型选择，购买后展示分润明细表；算法验证面板可单独试算三个公式。

**后台下单入口（v1.2）**：`server.js` admin 块新增 `POST /api/order/product`（`buyerId` 取请求体或 `?userId=` 覆盖）；`admin.js`「订单/会员」tab 新增「产品下单」卡片——买家（标注合伙人档位/代理身份）、产品（目录价）、数量、区域码、特色产品交付类型、行政费金额，联动 `/api/calc/product-price` 预览成交价，下单后展示分润明细表；订单列表兼容产品单（产品名/数量/实付，标记「幂等，不可编辑」）。

**状态口径修正（v1.2）**：巡查 5% 佣金仅「权归区县负责人」（门店交付）时为 `pending_allocation`；总部交付时该行金额已收归总部，状态按普通 `pending`（修 v1.1 仅按角色名置状态、未判 owner 的问题）。

**验证**：`scripts/verify_product_order.js` **82 条全 PASS**（十区块订单链路 + 总部交付巡查状态断言）；HTTP 冒烟 10/10（含收益台账 product 662.4、幂等重放、未知产品 400）；行政费 HTTP 复验（5000 → HQ 250/门店 250/HQ 4500 闭环）、两模式巡查状态复验通过。

## 十一、身份折扣体系与商城系统预留（v1.3）

> 用户 2026-10-23 强调：实物按身份折扣定价；**代理折扣与合伙人折扣是两套独立体系、力度不同，必须分开计算**；后续将建设商城系统。

**两套折扣表（分开维护，严禁混用）**：

| 体系     | 档位与折扣                                            | 存放                        |
| ------ | ------------------------------------------------- | ------------------------- |
| 合伙人折扣  | VIP 8 / 天使 7.5 / 私董 7 / 联创 6.5                  | `RA.PARTNER_DISCOUNT`     |
| 代理折扣   | 单店 5 / 区县 4 / 市代 3.5 / 省代 3                     | `RA.AGENT_DISCOUNT`       |
| 挂牌价(list) | 1.0（总部挂牌价对照）                                     | `productDiscount('list')` |

**单一档位解析入口** `PS.resolveBuyerLevel(buyer, agentRecord)`（订单创建、用户端商城、后台代下单共用，杜绝三处逻辑漂移）：

```
优先级：代理身份（拿货价）> 合伙人档位 > 原价(list)
返回：{ level, discountKind: 'agent' | 'partner' | 'list' }
```

- 代理折扣整体深于合伙人折扣，代理身份优先 = 买家最优价（默认口径，见 A10）。
- 订单显式记录 `discount_kind`（agent/partner/list）与 `level`，供对账与商城订单展示。

**商城报价 API** `GET /api/products`：

- 无参数：公共目录 + 两套折扣表（`discounts.partner` / `discounts.agent`）。
- 带 `?userId=X`（或登录态 token）：附加 `buyer`（身份解析结果）与 `prices`（逐产品成交价 + 合伙人价 + 代理拿货价三套对照，`PS.buyerProductPrices`）。

**UI 口径统一**：用户端「产品」tab 与后台「产品下单」预览均走同一解析——代理用户看到代理拿货价（双身份买家额外展示合伙人价对照），杜绝「看到的价 ≠ 实付的价」。

**算例**（p6 = 天使合伙人 + 单店代理，脑商Pad）：

```
合伙人价（天使 7.5折）= 5235      代理拿货价（单店 5折）= 3490
成交档位 = store（agent） → 实付 3490，订单 discount_kind = 'agent'
```

**验证**：`verify_product_order.js` ⑪ 区块 19 条（resolveBuyerLevel 优先序、两套表无交集键、双身份买家按代理折扣+落库 discount_kind、三套报价对照）；HTTP 8/8（公共目录/双身份报价/登录态解析/实际下单 3490）。

## 十二、多身份切换体系（v1.4）

> 用户 2026-10-23 要求：**允许同一账户同时持有 合伙人 / 区域代理 / 合店老板 三种身份**；前端做身份切换；合伙人是合伙人的收益、代理是代理的收益、合店老板是合店老板的收益，严格分离。

**身份收益分离映射** `commissionIdentity(c)`（routes.js，三身份流水之和 = 全量、不重不漏）：

```
product 类型按 subtype 细分：partner_product → partner；chain_*/card_*/featured_*/admin_* → agent（virtual_* 虚拟分成已废弃，2026-10-27 起 AI软件卡改走 card_*、陪练卡改走 featured_*）
其余按类型：partner = supply/direct/rebuy/parity/global/founding
            agent   = agent/region_vip/region_goods_diff/region_signing/region_admin_delivery/region_costore
            costore = costore
```

**身份列表 API** `GET /api/identities`（用户登录态；admin 块 `?userId=` 代查）：
- 只返回实际持有的身份：`agent` 需有代理记录、`costore` 需有合店记录才出现；`partner` 为基础身份始终显示
- 每身份带 `key/name/detail/month_income/by_type`；`total_month_income` = 各身份之和 = 全量

**分身份收益** `GET /api/commissions?identity=partner|agent|costore`（用户块透传、admin 块代查均支持，另支持 `type`/`period`）。

**前端身份切换**（app.js）：顶部切换栏 chips 展示全部身份 + 各身份本月收益（`title` 提示），点击切换后首页/收益页按当前身份过滤展示；「我的全部身份」卡可一键跳切。

**身份×折扣联动**：身份切换只改变收益查看维度与下单折扣口径——三身份买家下单按 `resolveBuyerLevel`（代理优先）成交，冒烟实测 p7 任命代理后 Pad 从 5235（合伙人 7.5 折）变为 3490（代理 5 折）。

**冒烟场景**（`scripts/smoke_identities_http.js`，28 条断言）：
1. admin 代下单：p6（天使+单店）Pad = 3490 agent；p7（纯合伙人）Pad = 5235 partner
2. admin 块身份端点代查（修复 admin 块 404）：p6 两身份 / p7 两身份 / 缺 userId 400
3. 造收入：p8 挂 p7 名下 → p7 任命 D2 单店代理（第三身份）→ p8 在 D2 下单 → 月度结算
4. 收益分离：p6 代理 14400 / 合伙人 0；p7 合伙人 1278（supply 480 + direct 798）/ 代理 2400 / 合店 69.8，三身份之和 = 全量 3747.8
5. 分身份明细类型纯净（agent 明细不含 costore、partner 明细不含 region_*）
6. p7 登录态自查三身份 + 分身份收益；登录态下单按代理折扣
7. 产品分润笔带 subtype（p5 收到 p6 Pad 单 partner_product 523.5）

**验证**：`verify_identities.js` **37 条全 PASS**（commissionIdentity 映射 10 + 三身份用户收益分离 + 过滤不重不漏 + 单/双身份 + 撤代理兜底）；HTTP 冒烟 28/28。

## 十三、身份销售额无直推奖 + 区域分成落地修正（v1.5）

### 13.1 规则：售卖身份 = 只赚差价

| 收益项 | 身份名额销售（VIP/天使/私董/联创） | 产品订单 | 代理技术费 |
|---|---|---|---|
| 供货差价 `supply` | ✅ 唯一收益 | — | — |
| 平级奖 `parity` | ✅ 与直接上级同级时触发 | — | — |
| 直推奖 `direct` | ❌ **不再产生** | ✅ 产品提成 `partner_product` | ✅ 直推代理奖 15% |
| 复购奖 `rebuy` | ❌ **不再产生** | ✅ flat2 回滚模式 | — |

**差价公式（分模式）**

| 模式 | 实付 | 卖方差价 |
|---|---|---|
| 零售整包（不传 `rawQuota`） | `RETAIL_PRICE[packageTier]` | `实付 − 卖家拿货成本`（`wholesaleCost(sellerTier, packageTier)`） |
| 批发补货（传 `rawQuota`） | `WHOLESALE[buyer.tier] × q`（买家本档价，2026-10-24 拍板） | `(WHOLESALE[买家本档] − WHOLESALE[卖家档]) × q`（上级赚买家本档价 − 自己本档价的差价，与名额档位无关） |

> 修复前：零售整包也套用 `supplySpread`（下级档价 − 卖家档价），当下级档价低于卖家档价（如天使卖私董 `6980 < 7500`）时算出负值并被 `if(spread>0)` 拦截 → 卖家差价被吞。现按代码注释本已声明的「实付 − 拿货成本」执行，retail 模式恒正；raw 模式保留 `supplySpread`（`wholesaleCost` 用的是整包 VIP 数，与单名额补货单位不同，不能一刀切）。

### 13.2 修正：合店费省市区分成落到真实代理

`settlement.runCostore` 旧实现调用 `costoreDistribution` 时不传 `provinceId/cityId/districtId`，函数默认值 `'PROV'/'CITY'/'DIST'` 成为**不存在的收款账户** → 省 2%/市 8%/区县 10% 永远到不了真实代理，还使「已记账合计」虚高、总部留存被低估。

修复：新增 `costorePlan.resolveRegionOwners(agents, regionCode)`：

1. `region_code` 精确匹配优先（与 `runAgent` 门店费口径一致）；
2. 该级只有唯一代理时归其（合店记录无区域码也能正确归属）；
3. 否则归总部 `HQ`（不再产生幽灵账户）。

### 13.3 供货链级差级联（v1.6，用户 2026-10-23 最终口径；2026-10-24 扩展至批发补货）

**核心恒等式**：终端价（零售价 / 下级档拿货价）= 卖方差价 + Σ 上级级差 + 总部底价（6,500/VIP = 门店服务费 3,000 + 总部费 3,500）。

**购买流程**（用户 2026-10-24 口述）：下级找上级买 → 上级找自己的上级买 → … → 直到链顶向总部买；
钱沿链向上逐层拆，名额由总部逐层发放到买方的上级——批发补货最终入买方账（可转售），升级整包则是买方的上级消耗自己购买的名额给买方升档（买方不入账）。

`createOrder` 沿 `buildUplineChain(seller)` 逐级落 `supply` 佣金（**零售整包 + 批发补货均生效**）：

```
prevUnit = WHOLESALE[seller.tier]
for u of 上级链:
    upUnit = (u 是链顶) ? HQ_PRICE_PER_VIP(6500) : WHOLESALE[u.tier]   # 链顶向总部拿货
    diff = (prevUnit − upUnit) × 名额
    if diff > 0: 落账给 u（type=supply，formula='供货链级差 (...)')
    prevUnit = upUnit
```

**rawQuota 批发补货同样级联**（2026-10-24 修正，旧口径「不加级联、余款直丢总部」已废）：
补货单的买家同样是「向上级链逐层拿货」，链式差价一路拆到总部底价；买方名额自动入账 `+rawQuota`（可转售），升级整包买方不入账（上级消耗自己购买的名额给买方升档）。

## 十四、分红池按月结算 + 三身份分账（v1.6，2026-10-23 用户确认）

### 14.1 合店费是一次性消费，分红池按月全平台一个池

- **合店费不做摊销**：最低 6 个月起购（起步 4,188 = 698×6），当期全额分配；10% 分红池**全额计入本月**，不按月摊 6 个月。
- **分红池与全球奖 / 创始奖同口径**：全平台一个池按月结算，**不按单店、不按单笔**各自成池。
  - 旧实现按 `store_id` 分组（每店独立池）→ 同一老板跨店会重复进池、店与店之间无法互济。
  - 现实现：`settlement.runCostore` 汇总本月全部合店费的 10%，一次性 `dividendSplit`。
  - 分红记录 `ref_order_id = NULL`（月度池，不对应单笔订单），`note` 标注 `全平台分红池(YYYY-MM/N笔)`。
- **分配规则不变**：一半按合格人数均分 + 一半按业绩占比；入股首月免考核（`graceMonths = 1`）。
- **兜底**：全平台池无合格合店老板（全员过无责期且未达标）→ 余款归总部 `HQ`，不给不合格者，也不偏向某个店长。

### 14.2 三身份分账（合伙人 / 合店店长 / 代理）

一个人最多同时持有三种身份，收益**分开记账、分开展示**，不再只给一个总数。

| 身份 | `identity` | 收入来源 |
|---|---|---|
| 合伙人 | `partner` | `supply` 供货差价/级差、`parity` 平级奖、`global` 全球奖、`founding` 创始奖、`product` 中 `partner_product` |
| 合店店长 | `costore` | `costore` 中门店服务/直推/复购兜底（`costore_store_*`）及分红池；上级业务奖（`costore_upline_*`）归「合伙人」栏 |
| 代理 | `agent` | `agent` 门店服务费、`region_*` 区域奖、`costore` 中 `subtype='region_costore'`：省 2% / 市 8% / 区县 10% / 总部 15% |

规则细节：
- **代理被赠联创/私董后参与全球奖、创始奖**（用户确认可参与），但该笔收益归「合伙人」身份，不新增第四类身份。
- 合店费里分给省/市/区县的 20% 归「代理」；门店服务 40% + 业务 15% + 分红池 10% 归「合店店长」。
- 代码：`routes.commissionIdentity` 判定；数据库：`commissions.identity`（CHECK 三值）+ `v_income_by_identity` / `v_identity_monthly` / `v_period_total` 三个视图。
