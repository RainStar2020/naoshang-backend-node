## 1. 系统定位

本平台是**脑商AI合伙人分润算法的可交互测试台**，用于：

1. **验证算法是否正确** —— 所有金额均由 `src/commission.js` / `src/settlement.js` / `src/regionAgent.js` 中的纯函数计算，无手写死值；任一参数变化，金额实时联动。
2. **验证功能是否齐全** —— 管理员端覆盖「建人 → 授代理 → 授合店 → 下单 → 补货 → 结算 → 报表」全链路；用户端覆盖「我的收益 → 收益明细 → 团队 → 区域/合店」。
3. **验证边界与规则** —— 代理资格（门店代理需天使档）、只升不降、名额不足拦截、解绑重绑等。

> 本平台是**测试台**，不是生产系统：数据存内存 + `data/db.json`，重启保留；无并发/无事务/无真实支付。

## 4. 核心业务规则

### 4.1 定价与拿货

| 档位 | 零售价 | VIP 名额 | 每 VIP 拿货价 |
|---|---|---|---|
| VIP | 9980 | 1 | 7980 |
| 天使 | 29800 | 3 | 7500 |
| 私董 | 59800 | 6 | 6980 |
| 联创 | 239800 | 24 | 6500 |

**总部基准价 6500/VIP** 拆为两块：
- **门店服务费 3000** → 省 100 / 市 200 / 区县 300 / 门店 2400（每 VIP）
- **总部产品费 3500** → 全球奖（150/VIP）、创始奖、总部留存

### 4.2 购买路由（电梯规则）
下级购买/升级**只能向其绑定的直接上级购买**，不得跨级。即使下级档位高于上级，上级仍按**自身档位**拿货价赚差价。

### 4.3 代理资格（两种语义）
| 类型 | 语义 | 门槛 | 赠予身份 |
|---|---|---|---|
| **门店代理** | 前置门槛（不改变身份） | 必须 **天使** 及以上 | 无 |
| **区县代理** | 身份授予 | 无 | **私董** |
| **市代理 / 省代理** | 身份授予 | 无 | **联创** |

身份**只升不降**：已是联创者被任命为市代，仍是联创。

### 4.4 奖池口径
- **直推奖**：新客 5%/10%/15%（按推荐人档位）；**复购奖** 2%
- **平级奖** 2%（级联，**2026-10-24 拍板·从供货上级的供货级差中扣除，非额外出账/总部吸收**；触发条件：转手方与其下级同级（拿货价相同、本跳吃不到差价）→ 平级奖 = 供货上级拿货价 × 2% × 出售名额个数，金额从该供货上级的级差中扣减）
- **全球奖**：池 = 150 × 当月全平台 VIP 总数；**半均分 + 半业绩**（业绩权重 = 本人直接卖出 + 团队子树 VIP）
- **创始奖**（按人各得全额，不分摊）：联创持创始奖 = 3500 × 0.5% = **17.5/VIP**；私董 = 3500 × 0.1% = **3.5/VIP**
- **直推代理奖**（tp123 新口径）：直系下级成为异地代理 → 基数（业务提点口径）× **15%**（算例 40000 × 15% = 6000）。**取代旧「区域开发奖 8%」**

### 4.5 合店费（698/月）—— 固定三分结构（2026-10-22 用户最终口径）

> **【2026-10-24 拍板 · 一次性入池】** 合店费按 698×6＝**4,188 一次性收取**；结算只在「入股当月」按全额 4,188 整笔分发**一次**（上表比例即占全额的比例，金额按 4,188 计＝表中各值 ×6），**不做 6 个月逐月摊销**。下表「金额（698）」为单月等价单位，便于核对分配比例，不代表每月实发。

**分配比例（均占合店费）**

| 归属 | 比例 | 金额（698） | 说明 |
|---|---|---|---|
| 总部 | 15% | 104.70 | |
| 省 | 2% | 13.96 | |
| 市 | 8% | 55.84 | |
| 区/县 | 10% | 69.80 | |
| **小计（总部体系）** | **35%** | **244.30** | |
| **门店老板** | **53%** | **369.94** | 多人门店按人数均分 |
| **推荐人（复购奖）** | **2%** | **13.96** | 归本单推荐人 `promoter_id`，不均分 |
| **合店店长分红池** | **10%** | **69.80** | 一半均分 + 一半业绩占比 |
| **小计（门店侧）** | **65%** | **453.70** | |
| **合计** | **100%** | **698.00** | |

**规则要点**
1. **固定结构，不分推荐人身份场景**（旧 S1/S2/S3 分流已废除）。
2. **推荐人 2% 即用户所说的「复购奖」**，归本单推荐人。若推荐人就是门店老板本人，则两笔叠加 = 55%（仍分两条流水记录，便于核对）。
3. **多人门店**：53% 按门店老板人数均分（如 2 人 → 各 26.5% = 184.97），均分余数（分单位）并入主门店老板，保证 100% 闭环。
4. **分红池 10% 分配方式**：一半（5%）按合店店长**人数均分**，另一半（5%）按各合店店长的**合店费业绩占比（`feePerf`）**分配。
5. **分红资格**：仅 `feePerf > 0`（实际做过推荐）的合店店长参与，未推荐者得 0。
6. **计算精度**：全程以「分」为整数单位分摊，余数归位，保证逐笔合计严格等于合店费。

### 4.6 区域代理（tp123 口径，2026-10-22 全面修订）

#### 4.6.1 级别与门槛费
| 级别 | 身份要求 | 品牌费 | 设备费 | 保证金 | 合计 |
|---|---|---|---|---|---|
| 省代 | 10 联创 | 200w + 60w | 30w | 30w | **260w** |
| 市代 | 联创 | 35w/30w/25w | 10w/5w/0 | 0/5w/0 | **45w / 40w / 35w**（按 >1000w / 500~1000w / <500w） |
| 区县代 | 私董 | 10w | 1w | 1w | **12w** |
| 单店 | 高级（天使） | 4w | 2w | 2w | **8w** |

#### 4.6.2 分成表
| 级别 | B端业务 | B端服务 | C端门店交付 | C端总部交付 | VIP合伙人奖 | 供应链 |
|---|---|---|---|---|---|---|
| 省代 | 20% | 10%(其中2%) | 10%(其中2%) | 10%(其中2%) | 200元(35元) | 3折 |
| 市代 | 18% | 8% | 8% | 8% | 165元(65元) | 3.5折 |
| 区县代 | 15% | — | 75% | 35% | 100元 | 4折 |
| 单店 | 15% | — | 65% | 30% | — | 5折 |

#### 4.6.3 实物产品（折扣制）
合伙人购买价 = 基准价（去成本，成本可为 0）× 折扣
- 合伙人：VIP 8折 / 天使 7.5折 / 私董 7折 / 联创 6.5折
- 区域代理：单店 5折 / 区县代 4折 / 市代 3.5折 / 省代 3折
- 上级合伙人另拿 **2% 复购奖**
- **级差 = (买方折扣率 − 卖方折扣率) × 基准价**

官方算例（平板 6980、成本 0）：
| 环节 | 金额 |
|---|---|
| 天使合伙人购买价 = 6980×0.75 | 5235 |
| 天使上级合伙人复购奖 = 5235×0.02 | 104.7 |
| 洛阳市代拿货价 = 6980×0.35 | 2443 |
| 洛阳市代收益 = 5235 − 2443 | **2792** |
| 总部收益 = 2443 − 104.7 | **2338.3** |

另一算例：VIP(0.8) 向单店(0.5) 进货 → 门店赚 6980×(0.8−0.5) = **2094**；单店(0.5) 向区县(0.4) 进货 → 区县赚 6980×(0.5−0.4) = **698**。

#### 4.6.4 虚拟产品（课程 / 会员卡 / 合店费）——按剩余比例分成
**不是折扣价差**，而是按实付金额直接比例分配：

| 交付方式 | 总部 | 省代 | 市代 | 单店 |
|---|---|---|---|---|
| 总部交付 | 55% | 2% | 8% | 35% |
| 门店交付 | 15% | 2% | 8% | 75% |

> 门店交付场景「总部 25%」= 省代 2% + 市代 8% + 总部 15%（截图原文包含关系），顶层等价 15% + 2% + 8% + 75% = 100%。
> 单店 75% 内部（相对分配池）：门店股东 0.5 / 推荐人 0.05~0.15 / 合店老板分红 0.1。

官方算例：私董买月卡实付 700，门店交付 → 总部 105 / 省 14 / 市 56 / 单店 525。

#### 4.6.5 门店交付分配
- 进入门店池比例 = 代理级别 C 端门店交付提点（单店 65% / 区县代 75% / 市代 8% / 省代 10%）
- 门店池按股东人数均分
- 推荐人复购奖 2% 由各股东均摊（从股东净额扣除）
- 差额（折扣额 − 门店池 − 复购奖）归其他代理层级，按分成表层级差分配

官方算例：折扣额 1600、单店、2 股东 → 门店池 1040（每人 520）、复购 32（每人 16）、人均净 **504**。

#### 4.6.6 行政费
集训营基础费用：**总部 5% + 销售门店股东 5% + 交付方 90%**（上课的团队）。

#### 4.6.7 区域代理收益总览（8 类）
1. **区域奖**：省 100 / 市 200 / 区县 300（每 VIP，来自 3000 门店服务费；门店店长 2400 走门店服务费分配）
2. **实物级差**：按折扣率差 × 基准价
3. **虚拟产品分成**：按 4.6.4 比例
4. **门店交付**：按 4.6.5
5. **行政费**：5% + 5% + 90%
6. **可分配提点**：成交额 5% 挂「待分配」，可认领至上级
7. **直推代理奖**：基数 × 15%
8. **VIP 合伙人奖**：省 200 / 市 165 / 区县 100（单店无）
9. **合店费提成**：省 2% / 市 8% / 区县 10%

## 6. 典型测试流程

**A. 验证普通合伙人收益**
1. 管理员登录 → 种子数据 → 恢复默认
2. 下单 Tab：买家 p4、档位 vip、原档 vip、名额 1、区域码 330110、新客=否（复购）→ 下单
3. 结算 Tab → 执行月度结算
4. 报表 Tab → 查看每人 total 与 byType
5. 用户端用 13800000001 登录 → 首页看「本月收益明细」逐笔核对

**B. 验证区域代理**
1. 种子恢复默认
2. 代理/合店 Tab → 任命 p1 省代(33)/市代(3301)、p5 区县代(330110)、p6 门店代(330110-S1)（层级码 + 显式父链）
3. 结算 → 用户端 13800000005 登录看「区域/合店」Tab 的区域收益

**C. 验证代理资格拦截**
1. 种子恢复默认后，新增一个 `tier: vip` 的合伙人
2. 任命其为门店代理 → 应被拒绝（需天使档）

**D. 验证算法公式（不落库）**
1. 管理员或用户端「算法验证」Tab
2. 区域奖 / 实物级差 / 虚拟产品分成 / 门店交付 / 代理分成表 / 区域总账 六个计算器直接出结果

**E. 逐笔对账（核心流程）**
1. `node scripts/audit_ledger.js --scenario=A`（或 B / C）→ 得到可手算的逐笔台账
2. 或：后台造数据 → 「结算」执行 → 「**逐笔明细**」Tab 看每一笔的公式
3. 按 `docs/手算核对指南.md` 第 4 节的公式逐条手算，对照第 5 节模板填表
4. 有对不上的，把「你的手算值 / 系统值 / 你认为的正确公式」发我

**F. 改 ID 验证（后台编辑能力）**
1. 后台「合伙人」Tab → 点某人的「编辑」→ 把 ID 从 `p4` 改成 `p99` → 保存
2. 验证级联：「订单/会员」Tab 里 p4 的订单买家已变成 p99；「逐笔明细」Tab 里 p4 的收益人变成 p99
3. 下级推荐关系、佣金、代理、合店记录同样同步
