# 脑商AI 合伙人 · 数据库设计文档

> 版本：v1.0（2026-10-23）
> 配套：后端内存数据层 `src/store.js#createDb()` + 持久化快照 `data/db.json`
> 交付物：`sql/schema.sql`（建表 + 外键）、`data/brain_biz.db`（空表，外键已连接）、`scripts/db_migrate.py`（建库 + 连接性验证）

---

## 一、设计目标

把当前「内存对象 + JSON 快照」的临时存储，上升为**可持久化、外键连接**的关系型数据库，承载：

- **合伙人**（联创/私董/天使/VIP，含合店老板角色）
- **代理**（省 / 市 / 县区 / 门店）
- **合店 / 门店**及其老板名单
- **订单 / 销售**（套餐包、产品销售 —— 收益来源）
- **收益 / 佣金**（供货差价、直推、复购、平级、区域门店费、全球奖、创始奖、合店分成、分红）
- **名额台账**（下发 / 消耗流水）
- **关系变更历史**、**后台配置**、**月度结算批次**

设计原则：

1. **人是 `partners` 表**：合伙人及其档位是核心；「合店老板」「代理」只是其身上的**角色**，通过 `co_stores` / `regional_agents` 关联，不另建「人」表。
2. **规范化展开**：JSON 里的 `coStores[].owners`（数组）拆成子表 `co_store_owners`（1:N），保证可被外键与索引连接、可被聚合查询。
3. **外键连接**：所有关联均声明 `REFERENCES`，并在连接开启 `PRAGMA foreign_keys=ON`（迁移脚本已开启），已通过 `PRAGMA foreign_key_check` 零违规验证。
4. **金额用 REAL（元，2 位小数）**；档位用 TEXT 枚举：`none / vip / angel / private / cofounder`。

## 二、ER 关系（外键连接总览）

```
                       partners（合伙人/合店老板，人）
                       ├── upline_id ──▶ partners.id            （合伙人链，自引用）
                       │
   orders（订单/销售）──┤  buyer_id  ──▶ partners.id
                       │  seller_id ──▶ partners.id
                       │
   commissions（收益）──┤  owner_id  ──▶ partners.id
                       │  ref_order_id ─▶ orders.id  (SET NULL)
                       │
   quota_ledger ────────┤  partner_id ──▶ partners.id  (CASCADE)
   quota_transactions ──┤  partner_id ──▶ partners.id  (CASCADE)
   regional_agents ─────┤  partner_id ──▶ partners.id  (CASCADE)
                       │  referrer_id ─▶ partners.id  (SET NULL)
                       │
   co_stores（合店）────┤  owner_id        ──▶ partners.id  (RESTRICT)
                       │  promoter_id     ──▶ partners.id  (SET NULL)
                       │  store_manager_id──▶ partners.id  (SET NULL)
                       │
   co_store_owners ─────┤  co_store_id ──▶ co_stores.id  (CASCADE)
                       │  partner_id   ──▶ partners.id  (CASCADE)
                       │
   upline_history ──────┤  partner_id / old_upline / new_upline ──▶ partners.id
```

**关键连接说明**

| 关系 | 父表 → 子表 | 含义 |
|---|---|---|
| 合伙人链 | `partners(upline_id)` → `partners(id)` | 推荐/上级层级（自引用，RESTICT 防误删） |
| 销售来源 | `orders(buyer_id/seller_id)` → `partners` | 谁买、谁卖（供货方=上级） |
| 收益归属 | `commissions(owner_id)` → `partners` | 收益发给谁；`ref_order_id` → `orders`（订单删除置空） |
| 名额持有 | `quota_ledger/quota_transactions(partner_id)` → `partners` | 可下发名额余额与流水 |
| 代理身份 | `regional_agents(partner_id)` → `partners` | 某人被任命为某区域代理；`referrer_id` 为开发人 |
| 合店老板名单 | `co_store_owners(co_store_id,partner_id)` | 一个合店有多名老板（1:N，已拆表） |
| 关系变更 | `upline_history(partner_id,...)` → `partners` | 解绑/重绑/改名历史 |
| 后台配置 | `settings(key,value)` | JSON 存储 costore 等可调参数 |
| 结算批次 | `settlements(period,summary)` | 月度结算结果归档（新增） |

### 3.3 commissions（收益 / 佣金）

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| id | TEXT PK | `commissions[id]` | 佣金号（确定性 id，幂等） |
| owner_id | TEXT FK | `commissions[owner_id]` | 收益归属人 |
| **identity** | TEXT NOT NULL | 由 `type`/`subtype` 推导 | **收益归属身份**：`partner`（合伙人）/ `costore`（合店店长）/ `agent`（代理），带 CHECK 约束 |
| type | TEXT | `commissions[type]` | `supply/parity/global/founding/agent/costore/product` |
| subtype | TEXT | `commissions[subtype]` | 细分（如 `agent_direct`/`storeService`/`partner_product`/`region_costore`；合店费：`costore_store_service`/`costore_store_direct`/`costore_store_repurchase`/`costore_upline_direct`/`costore_upline_repurchase`，另保留 `costore_owner` 作兜底） |
| period | TEXT | `commissions[period]` | 结算月 `YYYY-MM` |
| base_amount / rate / amount | REAL | `commissions[base_amount/rate/amount]` | 基数 / 比例 / 实际金额 |
| ref_order_id | TEXT FK→orders | `commissions[ref_order_id]` | 关联订单（月度池如分红池为 NULL） |
| status / note / formula | TEXT | `commissions[status/note/formula]` | 状态 / 备注 / 人话公式 |

#### 三身份分账规则（2026-10-23 用户口径）

一个人可同时持有三种身份，**收益必须按身份分开存储与展示**，不能只加总成一个数：

| 身份 | `identity` | 覆盖的佣金 `type` | 说明 |
|---|---|---|---|
| 合伙人 | `partner` | `supply` 供货差价/级差、`parity` 平级奖、`global` 全球奖、`founding` 创始奖、`product` 中 `subtype='partner_product'` | 代理被赠联创/私董后参与的全球奖、创始奖也归这一栏 |
| 合店店长 | `costore` | `costore` 中 `subtype='costore_store_service'`（门店服务 40%）/ `costore_store_direct`（13% 直推·店长兜底）/ `costore_store_repurchase`（2% 复购·店长兜底）/ 分红池；`costore_upline_direct`/`costore_upline_repurchase`（上级业务奖）归「合伙人」栏 | 合店业务收益（上级业务奖除外） |
| 代理 | `agent` | `agent` 门店服务费、`region_*` 区域奖、`costore` 中 `subtype='region_costore'`（省 2%/市 8%/区县 10%/总部 15%） | 区域代理收益 |

配套视图：

| 视图 | 用途 |
|---|---|
| `v_income_by_identity` | 人 × 身份 × 月 × 类型 的收益明细汇总（后台「分身份明细」） |
| `v_identity_monthly` | 人 × 身份 × 月 合计（前端身份切换卡 / 三身份收益卡） |
| `v_period_total` | 全平台当月三身份合计（资金闭环核对：三身份 + 总部留存 = 实收） |

## 四、连接性验证（已执行）

运行 `python scripts/db_migrate.py`：

1. 依据 `sql/schema.sql` 在 `data/brain_biz.db` 生成**空表 + 外键**的正式库（交付物）。
2. 若 `data/db.json` 存在，灌入**临时库**并开启外键，执行：
   - `PRAGMA foreign_key_check` → ✅ 零违规；
   - 抽样 `orders.buyer/seller` 悬空记录 = 0；
   - 抽样 `co_store_owners` 悬空记录 = 0。
3. 临时库验证后删除，交付库始终保持**空表**。

> 当前 `db.json` 种子态示例：partners 7 / orders 3 / commissions 5 / quota_ledger 7 / regional_agents 2 / co_stores 1 —— 全部外键连通，无悬空引用。

## 五、迁移到关系库的注意事项（与现有逻辑的衔接）

1. **`coStores[].owners` 展开**：写库时把数组拆入 `co_store_owners`；读库时 `SELECT ... GROUP BY co_store_id` 聚合回去。
2. **`users` 是对象（键=ID）**：导入时枚举键；`quotaLedger` 同理。
3. **`is_founding` 在 store.js 里被写成 `'founding'/'none'` 字符串**（不是布尔），导入映射保持一致。
4. **级联策略**：合伙人被删时，`quota_*` / `regional_agents` / `co_store_owners` / `upline_history` 级联删除；`orders/commissions/co_stores` 用 `RESTRICT` 防误删（与 store.js 的 `deletePartner` 保护逻辑一致）。
5. **金额精度**：应用层统一 `round2`（四舍五入到分）；库内 REAL 存储，统计时建议 `ROUND(SUM(amount),2)`。
6. **档位枚举约束**：可在应用层校验，SQLite 不强制；如需强约束可在写入前校验 `tier IN (...)`.

## 六、典型查询示例

```sql
-- 某合伙人全口径收益
SELECT type, SUM(amount) AS total
FROM commissions WHERE owner_id = 'A' GROUP BY type;

-- 某门店（D1-S1）合店老板名单与业绩
SELECT p.name, o.performance
FROM co_store_owners o JOIN partners p ON p.id = o.partner_id
WHERE o.co_store_id = 'cs_xxx';

-- 某区域代理当月门店费
SELECT a.region_type, SUM(c.amount) AS fee
FROM commissions c JOIN regional_agents a ON a.partner_id = c.owner_id
WHERE c.type='agent' AND c.period='2026-10' GROUP BY a.region_type;

-- 合伙人链（递归上级）
WITH RECURSIVE up(id, upline_id, lvl) AS (
  SELECT id, upline_id, 0 FROM partners WHERE id='E'
  UNION ALL
  SELECT p.id, p.upline_id, u.lvl+1 FROM partners p JOIN up u ON p.id = u.upline_id
) SELECT * FROM up;
```

## 七、与既有 `naoshang.db` 的区别

`data/naoshang.db` 是**鉴权/用户注册**库（`users`/`sms_codes`，见 `src/db.js`），与本设计无关。本设计针对**合伙人业务域**（收益/代理/合店/名额），落地为 `data/brain_biz.db`。两套库可并存，分别服务「登录鉴权」与「分润业务」。
