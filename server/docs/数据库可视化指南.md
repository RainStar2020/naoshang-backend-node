## 一、结论速览：数据库在哪、长什么样

这个项目**没有单一数据库**，而是「三层存储」并存。看数据前先搞清去哪一层：

| 层 | 文件 | 技术 | 数据状态 | 用途 |
|---|---|---|---|---|
| ① 运行时真数据 | `server/data/db.json` | JSON 快照 | **有数据**（19 个集合） | 后端真正读写的地方 |
| ② 正式结构库 | `server/data/brain_biz.db` | SQLite | **45 张表全空** | DDL + 外键约束（迁移目标空壳） |
| ③ 建表脚本 | `server/sql/schema.sql` | SQL DDL | 45 表 / 40 外键 / 0 条 INSERT | 权威结构定义 |

**为什么 ② 是空表？** 这不是数据丢了，是设计如此。`server/docs/数据库设计.md` 写明：
`brain_biz.db` 是「空表 + 外键」的正式交付库；验证时把 `db.json` 灌进**临时库**跑
`PRAGMA foreign_key_check`，通过后删除临时库，交付库始终保持空表。

**运行时存储模式**：`server/src/dbLayer.js` 默认 `DB_KIND=memory`，走内存适配器
（委托 `src/store.js`），写盘靠 `server.js` 的 `saveDb()` 整份覆盖 JSON。
PostgreSQL 适配器（`pg` 已在 `package.json`）**只是骨架**，注释明确写了
「PG 适配未连真实库」，需配 `DATABASE_URL` + `DB_KIND=pg` 才启用。

## 二、看结构：三种方式

### 方式 A（推荐，最快）：一键导出带数据的可视化库

```bash
cd E:\脑商ai\server
node scripts/export_view_db.js
```

产出 `server/data/brain_biz_view.db` —— **完整 schema + 真实数据**合一的 SQLite 单文件。
脚本复用了 `db_health.js` 导出的 `populateSqlite()`，灌完库立即跑外键自检，
导出结果保证「结构完整、数据真实、外键零违规」。

`quotes` 42 / `skus` 18 / `activation_codes` 9 / `regional_agents` 4 /

### 方式 B（零安装）：内置网页浏览器

```bash
cd E:\脑商ai\server
node scripts/db_viewer.js          # 打开 http://localhost:7788
```

三个页签：**数据**（分页浏览真实行）/ **结构**（列定义 + PK/FK/NOT NULL 标注）/
**关系**（本表出向外键 + 被引用的入向关系）。左侧按业务分组列出 45 张表，
顶部显示表数/有数据表数/总行数/外键数。纯 Node 内置模块，无任何依赖。

### 方式 C（标准 GUI 工具）

把 `brain_biz_view.db` 拖进任一工具即可：

| 工具 | 操作 |
|---|---|
| DBVisualizer | 新建 SQLite 连接 → 选 `data/brain_biz_view.db` |
| DBeaver | 新建 SQLite 连接 → 选该文件 → 「数据库」视图看 ER 图 |
| Navicat Premium | 新建 SQLite 连接 → 选该文件 → 「设计」看结构 |
| VS Code | 装 SQLite Viewer 扩展 → 右键文件 → Open Database |

### 原始结构文件（要看权威定义）

- 库结构定义：`server/sql/schema.sql`（45 个 `CREATE TABLE` + 40 处 `REFERENCES`）
- 设计文档：`server/docs/数据库设计.md`（ER 图、外键策略、迁移注意事项）
- 迁移脚本：`server/scripts/db_migrate.py`（建库 + 连接性验证）
- 健康检查：`server/scripts/db_health.js`（外键校验、孤儿记录检测、`--fix` 修复）

## 四、关键提醒

1. **数据不在 Git 里**。`server/.gitignore` 忽略了 `data/db.json` 和 `data/*.db`。
   `db.json` 是当前唯一的真实数据载体，误删无法从版本库恢复 —— 建议定期单独备份。
2. **`brain_biz_view.db` 是派生产物**，可随时用 `export_view_db.js` 重新生成。
3. **别直接往 `brain_biz.db` 塞数据**。它是空表交付物，运行时用不到；
   业务数据走 `db.json`。
4. 切换到 PostgreSQL 时，`dbLayer.js` 的 PG 适配器需补完；`docs/数据库设计.md` 第五节
   列了 6 条迁移注意事项（JSON 数组拆子表、`users` 是对象需枚举键、`is_founding` 存的是
   字符串不是布尔、级联策略与 `deletePartner` 保护逻辑对齐、金额用 REAL + `round2`、
   档位枚举在应用层校验）。
