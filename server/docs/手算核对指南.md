# 逐笔收益手算核对指南

> 目的：让你用纸笔独立算出每一笔收益，与系统输出逐条比对，判断底层算法是否正确。
> 用法：先跑 `node scripts/audit_ledger.js --scenario=A`，拿到系统结果 → 按本文第 4 节的公式手算 → 对照第 5 节的表。

---

## 1. 三种核对方式（按效率排序）

| 方式 | 入口 | 适合 |
|---|---|---|
| **A. 台账脚本**（最快） | `node scripts/audit_ledger.js --scenario=A` | 每个场景变量都写死，一屏看完所有笔 |
| **B. 后台逐笔明细** | 浏览器 → `/?as=admin` → 「逐笔明细」Tab | 用自己造的任意数据核对，支持按类型筛选 |
| **C. 单点计算器** | 「算法验证」Tab（用户端/后台都有） | 只验一条公式（如级差、虚拟产品分成） |

## 2. 台账脚本用法

```bash
cd E:\脑商ai\server

node scripts/audit_ledger.js --scenario=A     # 打印场景 A 台账
node scripts/audit_ledger.js --scenario=B     # 场景 B：新客直推
node scripts/audit_ledger.js --scenario=C     # 场景 C：含合店费
node scripts/audit_ledger.js --scenario=A --save   # 写入 docs/核对台账-A.md
node scripts/audit_ledger.js --scenario=A --json   # 输出 JSON
```

台账输出 6 段：
1. **参与人** —— 每人 ID / 等级 / 上级 / 名额 / 代理身份
2. **订单** —— 买家→卖方 / 档位 / 名额 / 实付 / 拿货成本 / 供应差价
3. **结算概览** —— VIP 数、奖池、结算新增、当月全量
4. **逐笔收益明细** ← **你要核对的表**，每行带计算公式
5. **按人汇总** ← 对照你手算的「每人应得」
6. **闭环校验** —— 系统内部自洽性（✅ 只说明自洽，不等于业务口径正确）

## 3. 三个场景在验什么

### 场景 A · 最小闭环（9 笔）
```
p1 联创(持创始奖·省代33/市代3301兼任) → p2 私董(区县代330110) → p3 天使(单店代理330110-S1) → p4 VIP
订单：p4 向 p3 买 1 个 VIP（老客复购口径）
```
验的是**一笔订单能穿透出哪些收益**：供应差价、复购奖、全球奖、创始奖×2、区域奖×4（省100/市200/区县300/门店2400）。

### 场景 B · 新客直推（9 笔）
```
p1 联创(持创始奖) → p2 私董 → p3 天使(新客)
订单：p3 向 p2 买 1 个 VIP（buyerIsNew=true → 出直推奖而非复购奖）
```
验的是**直推奖比例按卖方档位取**：p2 是私董 → 15%。

### 场景 C · 含合店费（16 笔）
```
在场景 A 基础上加：p5 合店老板（天使），由 p3 推荐（promoter_id=p3）
```
验的是**合店费 698 的固定三分拆分（7 笔）**：
总部 15% + 省 2% + 市 8% + 区县 10% + 门店老板 53% + 推荐人 2% + 分红池 10%。

## 4. 逐条计算公式（手算用）

### 4.1 供应差价
```
差价 = 买家实付 − 卖方按自身档位的拿货成本
拿货成本表（每 VIP 名额）：
  VIP 7980 | 天使 7500 | 私董 6980 | 联创 6500
实付规则：
  原始名额售卖 → 买家档位价 × 名额数
  整包升级     → 零售价（VIP 9980 / 天使 29800 / 私董 59800 / 联创 239800）
```

### 4.2 直推奖 / 复购奖
```
新客 → 直推奖 = 实付 × 卖方档位比例
       VIP 5% | 天使 10% | 私董 15% | 联创 15%
老客 → 复购奖 = 实付 × 2%
```

### 4.3 平级奖（2026-10-24 拍板：从供货上级级差中扣）
```
平级奖 = 供货上级拿货价 × 2% × 名额数
```
- 触发：沿「买家→卖家→卖家上级链」逐跳，若某转手方与其下级**同级（拿货价相同、本跳吃不到差价）**，则该转手方拿平级奖。
- 资金来源：**从供货上级的供货级差中扣除**（非额外出账、非总部吸收），钱严格守恒。
- 旧模型用「买家套餐档位」判定同级，会漏掉「卖家上级与卖家同级」这一类；新模型改用实际拿货价逐跳判定，并已修正。
- 例（用户原话）：天使 A 的同级下级 B 找 A 买名额（A/B 拿货价均 7500 → A 不赚钱），A 的上级为联创 C（A 7500 买、C 6500 买、卖给 A 按 A 拿货价 7500 → C 赚 1000），则平级奖 = C 拿货价 6500 × 2% × 名额，从 C 的 1000 级差里扣，发给 A。

### 4.4 全球奖
```
奖池 = 150 × 当月全平台 VIP 总数
分配 = 半均分 + 半业绩
  业绩权重 = 本人直接卖出 + 团队子树 VIP
```
> 需先算出「每个联创的业绩权重」，再按权重切业绩那半池。

### 4.5 创始奖（按人各得全额，不分摊）
```
联创（持创始奖）= 3500 × 0.5% × 当月VIP总数 = 17.5 × VIP数
私董（全员）      = 3500 × 0.1% × 当月VIP总数 = 3.5  × VIP数
```

### 4.6 区域奖（门店服务费 3000/VIP 拆分）
```
前提：只有「门店老板」身份售出的合伙人名额，才算门店售出。
      合伙人身份 / 合店老板身份卖出 → 合伙人售卖通道 → 本项为 0（3000 归总部）。

门店售出时，总部从 6500 中拿出 3000 作「门店服务费」：
  门店店长 2400 | 区县代 300 | 市代 200 | 省代 100   （合计 3000 闭环）
没配代理的层级，金额归总部（HQ）。现已支持「结构化层级码 + 显式父链」归集：门店渠道订单自动携带 `store_code`（门店码），结算从门店码按 `parent_code` 逐级向上归集 门店→区县→市→省，门店码 ≠ 区县码也不再掉总部（2026-10-24 落地）。
```

### 4.7 合店费（698/月）—— 固定三分结构

> **【2026-10-24 拍板 · 一次性入池】** 合店费按 698×6＝**4,188 一次性收取**，结算只在「入股当月」按全额 4,188 整笔分发一次（下表比例为占全额比例，金额按 4,188 计＝各值 ×6），**不做 6 个月逐月摊销**。下例「698」为单月等价单位，便于核对分配比例。

```
① 总部体系 35% = 总部 15% + 省 2% + 市 8% + 区/县 10%
     698 × 15% = 104.70   × 2% = 13.96   × 8% = 55.84   × 10% = 69.80   小计 244.30
② 门店侧 65%
     门店老板 53%        698 × 53% = 369.94
     推荐人复购奖 2%      698 ×  2% =  13.96   （归 promoter_id）
     合店店长分红池 10%  698 × 10% =  69.80
                        小计 453.70
③ 闭环 244.30 + 453.70 = 698.00 ✅

多人门店：53% 按人数均分（2 人 → 各 26.5% = 184.97）
推荐人 = 门店老板本人：53% + 2% = 55% = 383.90（分两条流水）
分红池：一半按人数均分 + 一半按 feePerf 业绩占比（仅 feePerf>0 参与）
```

**手算示例（分红池 69.8，2 名合店店长）**

| 店长 | feePerf | 业绩占比 | 业绩半池 34.9 | 均分半池 34.9/2=17.45 | 合计 |
|---|---|---|---|---|---|
| A | 60 | 60% | 20.94 | 17.45 | 38.39 |
| B | 40 | 40% | 13.96 | 17.45 | 31.41 |
| 合计 | 100 | 100% | 34.90 | 34.90 | **69.80** ✅ |

### 4.8 实物级差（tp123 折扣制）
```
级差 = (买方折扣率 − 卖方折扣率) × 基准价
合伙人折扣：VIP 8折 / 天使 7.5折 / 私董 7折 / 联创 6.5折
代理折扣  ：单店 5折 / 区县 4折 / 市 3.5折 / 省 3折
上级合伙人另拿 2% 复购奖
```

### 4.9 虚拟产品分成（tp123 按剩余比例）
```
总部交付：总部 55% | 省 2% | 市 8% | 单店 35%
门店交付：总部 15% | 省 2% | 市 8% | 单店 75%
  （门店交付的「总部25%」= 省2% + 市8% + 总部15%）
单店 75% 内部：门店股东 0.5 | 推荐人 0.05~0.15 | 合店老板分红 0.1
```

### 4.10 行政费
```
总部 5% + 销售门店股东 5% + 交付方 90%
```

### 4.11 直推代理奖（tp123）
```
= 基数（业务提点口径）× 15%     官方算例：40000 × 15% = 6000
```

## 6. 在后台用你自己的数据核对

1. `http://127.0.0.1:3000/?as=admin` 进入后台
2. 「合伙人」Tab → 新增/编辑你要的人（**可以改 ID**，改 ID 会级联更新所有关系）
3. 「订单/会员」Tab → 下单（可改订单 ID、买家、卖方、金额等）
4. 「代理审核」Tab → 任命省代/市代/区县代/单店代理
5. 「门店管理」Tab → 登记合店
6. 「结算」Tab → 执行月度结算
7. 「**逐笔明细**」Tab → 看每一笔的「基数 / 比例 / 金额 / 计算公式」，按第 4 节公式手算比对

## 7. 怎么反馈问题

发现对不上时，请给我这 4 样，我就能定位：
1. **场景/订单**：用的是哪个场景，或后台造的什么数据
2. **你的手算值**：每一笔你算的是多少
3. **系统值**：逐笔明细里那一笔显示多少
4. **你认为的正确公式**：用文字或公式写出来

我拿到后会：改 `src/` 底层算法 → 同步更新 `scripts/verify_region_agent.js` 断言 → 重跑台账验证 → 告诉你改了哪一行。
