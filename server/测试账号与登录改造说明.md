## 一、登录方式已改为「账号密码登录」

### 改动内容

家长（parent）通道的登录接口 `POST /auth/sessions`（别名 `POST /auth/login`）
**不再支持仅凭手机号免密直接发 token**，现在必须同时提供 `phone` + `password`：

| 情况 | 状态码 | 提示 |
|---|---|---|
| 手机号 + 正确密码 | 200 | 返回 token |
| 手机号 + **错误密码** | 401 | 手机号或密码错误 |
| 只给手机号、**不给密码** | 400 | parent 登录需 password |
| 未注册手机号 + 密码 | 404 | 未找到该手机号对应的合伙人 |
| 账号从未设置过密码 | 403 | 该账号尚未设置密码，请先注册或重置密码 |

涉及文件：`server/src/routes/h5.js`（`/auth/sessions` 分支）

### 未改动的部分

- **健脑官（coach）** 通道：仍按 `loginAccount` 登录，逻辑未动。
- **管理员（admin）** 通道：仍按管理员密码登录，逻辑未动。
- **注册 / 找回密码** 的短信验证码流程：完全保留，未改动。
- 密码存储仍是 `scrypt` 加盐哈希（`scrypt$salt$hash`），**不落明文**；
  存量明文密码在首次登录成功时自动升级为哈希。

### ⚠️ 顺序很重要：停服 → 生成种子 → 起服

后端是「内存 + db.json 快照」架构：**服务启动时把 db.json 读进内存，之后每次写操作都会把
整份内存覆盖写回 db.json**。如果服务是在生成种子**之前**启动的，它内存里就是旧数据，
下一次写操作会把刚生成的种子数据整份冲掉（表现为"种子账号莫名其妙全没了"）。

### 「端口 3000 已被占用」其实是好消息

服务由计划任务托管时，端口上跑的就是**它自己**。所以现在**两条启动路径**都会识别这种情况：

**① 用 `node scripts/run.js start`（推荐）** —— 幂等，退出码 0：

```
✔ 脑商AI 已在运行（端口 3000），无需重复启动。
  API     : http://localhost:3000   (pid=12048)
  局域网  : http://192.168.0.44:3000   ← 手机 / 小程序用这个
```

**② 从 IDEA 直接跑 `node server.js`** —— 同样识别，不会再误报"服务无法启动"：

```
✔ 端口 3000 上已经有本项目的服务在运行（PID 12048），无需重复启动。
  访问地址： http://localhost:3000/
  局域网  ： http://192.168.0.44:3000/   ← 手机 / 小程序用这个

  若你就是想从 IDEA 里调试这个实例，二选一：
    停掉常驻服务再跑 → node scripts/run.js stop
    或换个端口启动     → PORT=3001 node server.js
```

只有当端口被**别的程序**占用时，才会报 `[FATAL]`。
看到"端口已被占用"**不要再 stop** —— 那会把好好在跑的服务关掉。先跑 `status` 看一眼。

### 测试数据不见了怎么办

管理端「恢复默认种子」(`/api/seed/reset`) 会把 `db.users` 重置成 7 个默认合伙人，
**测试账号会被一起清掉**（这是该接口"重置"的语义）。恢复只需一条命令：

```bash

```

它会自动按「停服 → 写种子 → 起服」的顺序执行，不会出现"写完又被内存快照冲掉"的情况。

### 三道防线（防止数据被莫名冲掉）

后端是「内存 + db.json 快照」架构：每个进程持有整份内存，**任何一次写操作都会把整份内存
覆盖写回 db.json**。只要有两个进程指向同一个 db.json，后写的就会用旧快照把另一个盖掉 ——
这是"测试数据反复消失、变回 7 个默认合伙人"的真正机制。现在有三道防线：

| 防线 | 作用 |
|---|---|
| ① `run.js stop` 会**验证端口真的释放** | 之前 stop 静默失败 → 调用方以为停干净了 → 在服务还活着时写库 → 被覆盖。现在没释放会明确报警 |
| ② **单实例锁** `data/db.json.lock` | 进程启动时记录 PID；发现已有存活实例在写这个库 → 本实例自动改用独立副本 `db.debug-<端口>.json`，绝不抢同一个文件 |
| ③ **端口自动避让** | 端口被本项目占着 → 自动往后找空闲端口（3001…）并配独立副本 |

实测：主实例持锁 + 第二实例写操作 → 真实库 mtime **毫发不变**。

> `.lock` 与 `db.debug-*.json` 已进 `.gitignore`。

### ⚠️ 关键：登录后必须把会话写进 storage

```js
// src/services/auth.js
export async function loginByPhone({ phone, password }) {
  if (!validPhone(phone)) throw new Error('请输入正确的手机号')
  if (!password || password.length < 6) throw new Error('请输入正确的密码')
  return login({ phone, password, channel: 'parent' })   // ← 必须用 api.js 的 login()
}
```

**为什么不能自己 `request()`**：会话（token）必须落到 `naoshang-session` 这个 storage key。
漏掉这一步，后端登录其实**成功了**，但本地没有 token →
下一个接口不带 `Authorization` → 后端返回 401 →
`api.js` 的 `request()` 触发 `logout()` → `reLaunch('/pages/login/index')` →
**表现就是「输对账号密码、点登录又弹回登录界面」，而且不报任何错**。

`api.js` 的 `login()` 已经把「校验 token/user → 写 storage」这套逻辑收在一处，
所以家长通道直接复用它，不再各写一份。
