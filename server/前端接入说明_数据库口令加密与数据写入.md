# 脑商AI · 前端接入说明（数据库口令加密规则与数据写入方式）

> 面向前端开发同学。本文档说明：**如何连接数据库**、**用户口令的加密规则**、以及**前端该通过什么方式向数据库添加数据**。
>
> 文档版本：2026-10-28 ｜ 对应后端版本：`E:\脑商ai\server` ｜ 数据库：MySQL 8.4.9

---

## 0. 先看这一条（最重要）

> **前端不要直连 MySQL 写业务数据。所有「新增/修改业务数据」必须走后端 HTTP API。**
>
> 原因：当前系统的**数据真源是后端的 `data/db.json`**，MySQL 是一份**只读镜像**（每 5 秒自动同步一次）。如果前端直接对 MySQL 执行 INSERT/UPDATE：
>
> - 写入的数据会在**最多 5 秒内被同步器覆盖掉**（同步器整表重建）；
> - 前端以为是"保存成功"，实际数据已经丢失；
> - 更糟的是会造成 db.json 与 MySQL 两边不一致，污染后续结算与对账。
>
> **MySQL 的用途**：给前端/测试/运营**查数据、看报表、排查问题**，以及供 IDEA 等工具可视化。
> **写数据**：一律走 API，改完数据 MySQL 会自动跟着更新，前端再查就能看到最新值。

## 2. 用户口令的加密规则 ⭐

这是前端最容易踩坑的地方，**前端不需要自己实现加密**，但需要知道库里存的是什么、以及为什么不能直接写明文。

### 2.1 算法规格

| 项目 | 值 |
|---|---|
| 算法 | **scrypt**（Node.js `crypto.scryptSync`） |
| 参数 | `N=16384, r=8, p=1` |
| 输出长度 | 64 字节 |
| 盐 | 16 字节随机（`crypto.randomBytes(16)`） |
| 存储格式 | `scrypt$<盐 hex>$<哈希 hex>` |
| 明文预处理 | `password.normalize('NFKC')`（Unicode 规范化） |
| 比对方式 | `crypto.timingSafeEqual`（防时序侧信道攻击） |

**实际存库的样子**（`users.password` 字段，varchar(255)）：

```text
scrypt$b9e6d627cf30c2ae65443d6cad8cac6d$1e53c82051a16ec4c5a4007e4a231fe6da9f7bcb0860937eb858dc2474a94e7b83dae0154da791e7888179dc7639e3f86121ad27260759c900fb9f2271a2b0c9
└─────┬──────────────────────────────────┘ └────────────────────────────────────────┬─────────────────────────────────────────────────────────────────┘
   算法标识        盐（32位hex = 16字节）                        哈希（128位hex = 64字节）
```

### 2.2 前端需要知道的 4 条规则

1. **前端永远不处理哈希**。注册/改密码时，把**明文**通过 API 传给后端，后端负责加盐哈希后入库。前端拿到的是 `token`，不是密码。
2. **库里没有明文密码**，永远查不到。调试时看到 `scrypt$...` 是正常的，不是脏数据。
3. **同一个密码每次注册存的值都不一样**（盐随机），所以**不能靠比对哈希字符串判断两个密码是否相同**，必须用 scrypt 验算。
4. **口令强度要求**（后端强校验，前端要同步做校验，避免用户提交后才报错）：

   | 接口 | 规则 | 报错 |
   |---|---|---|
   | 注册 `/auth/registrations` | **8-20 位，且同时包含字母和数字** | `WEAK_PASSWORD` |
   | 重置密码 `/auth/password-resets` | 至少 6 位 | `新密码至少 6 位` |
   | 修改密码 `/me/password-changes` | 至少 6 位 | `新密码至少 6 位` |

   > 注意：注册是 8-20 位，重置/修改是 ≥6 位，这是后端现有的两套口径，前端按接口区分。

### 2.3 存量明文升级（后端已自动处理）

历史上部分用户密码以**明文**存于 db.json。后端在启动时会自动把它们升级为 scrypt 哈希（`server.js` 的 `migratePasswords()`），并在用户首次登录成功后即时升级（`upgradeIfPlaintext`）。

**前端影响**：无。若某用户密码仍是明文（库里看到的是非 `scrypt$` 开头的值），属存量残留，后端登录时会自动迁移，前端无需特殊处理。

### 2.4 其他敏感字段的存储口径

| 表.字段 | 存储方式 |
|---|---|
| `users.password` | scrypt 哈希串（见上） |
| `users.password_migrated_at` | 升级为哈希的时间戳（毫秒） |
| `sms_codes.code` | 短信验证码**明文 6 位数字**（一次性，用后 `used=1`） |
| `sms_codes.expires_at` | 过期时间戳（毫秒） |
| `password_resets.ticket` | 重置票据（一次性令牌，10 分钟有效） |
| `pay_accounts.token` | 对外凭据 `payee_xxx`（不暴露库内主键） |
| `pay_accounts` 完整卡号 | **只存本表**，对外接口只返回脱敏值 |

> `sms_codes` 是当前唯一在库里存明文的敏感字段（验证码本身有 60 秒频控 + 一次性 + 有效期三重保护）。

## 3. 前端怎么「向数据库添加数据」——走 API

### 3.1 后端地址

| 场景 | 地址 |
|---|---|
| 本机调试 / IDEA 调试 | `http://127.0.0.1:3000` |
| 小程序真机 / 局域网其他机器 | `http://192.168.0.44:3000` |

前端已配置在 `E:\脑商ai1\.env`：

```bash
VITE_API_BASE_URL=http://192.168.0.44:3000
```

> ⚠️ 小程序真机**不能用 127.0.0.1**（那指向手机自己），必须用手机能访问到的局域网 IP。换 WiFi 后 IP 会变，需同步改这里和 `src/config/index.js` 的兜底常量。
> 微信开发者工具需勾选「不校验合法域名」；手机需与电脑同一 WiFi。

### 3.2 两层路由（注意路径没有 `/api` 前缀）

| 层 | 前缀 | 用途 |
|---|---|---|
| **契约层** | `/auth/*` `/me/*` `/partner/*` `/orders/*` `/wallet/*` … | **前端业务接口走这层** |
| 管理引擎 | `/api/*` | 算薪结算引擎 + 总部后台（需管理员权限） |

> 契约层**不带 `/api` 前缀**。前端现有代码调 `/auth/login` 是对的。

### 3.3 认证相关接口（写数据必看）

| 功能 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 发短信验证码 | POST | `/auth/sms/send` | body: `{ phone, purpose }`，`purpose` ∈ `register` / `reset-password` / `login`。同一手机号 **60 秒内只能发一次** |
| 注册（新增用户） | POST | `/auth/register` | body 见下 |
| 登录 | POST | `/auth/login` | body: `{ phone, password }` |
| 校验重置票据 | POST | `/auth/password/verify` | body: `{ phone, code }` |
| 重置密码 | POST | `/auth/password/reset` | body: `{ resetTicket, password }` |
| 修改密码 | POST | `/auth/password/change` | body: `{ oldPassword, newPassword }` |

> **别名说明**：`/auth/register` 等短路径是**别名**，内部映射到 RESTful 原路径：
> `/auth/register` → `/auth/registrations`；`/auth/login` → `/auth/sessions`；`/auth/sms/send` → `/auth/sms-challenges`。
> **别名仅在 POST 上生效**；GET 语义仍走 REST 原路径。前端两种都能用，建议沿用现有别名。

### 3.4 注册接口完整示例

**第 1 步：发验证码**

```http
POST http://127.0.0.1:3000/auth/sms/send
Content-Type: application/json

{ "phone": "13800138000", "purpose": "register" }
```

响应：

```json
{ "retryAfter": 60, "expiresAt": 1793154961386 }
```

**第 2 步：注册**（`code` 用上一步短信收到的验证码）

```http
POST http://127.0.0.1:3000/auth/register
Content-Type: application/json

{
  "phone": "13800138000",
  "code": "884172",
  "password": "User12345",
  "confirmPassword": "User12345",
  "name": "张三",
  "inviteCode": "",
  "gender": "male",
  "regionCodes": ["33", "3301", "330106"],
  "regionNames": ["浙江省", "杭州市", "西湖区"]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `phone` | ✅ | 11 位手机号 |
| `code` | ✅ | 短信验证码（一次性，用后失效） |
| `password` | ✅ | **8-20 位，含字母和数字** |
| `confirmPassword` | ✅ | 须与 `password` 一致 |
| `inviteCode` | ❌ | 邀请码（绑定推荐关系） |
| `name` | ❌ | 昵称，缺省用手机号 |
| `gender` | ❌ | `male` / `female` |
| `regionCodes` | ❌ | **必须 3 级**地区编码数组，否则地区信息不落库 |
| `regionNames` | ❌ | 与 `regionCodes` 对应的名称数组 |

成功响应：

```json
{
  "ok": true,
  "token": "user-34t9gv3921y",
  "user": { "id": "u_3y52lp", "name": "张三", "role": "user", "displayId": "QZ0019" },
  "entitlement": { "state": "never_paid", "amount": 200 },
  "accountType": "parent",
  "expiresAt": null
}
```

**后续请求带 token**：

```http
Authorization: Bearer user-34t9gv3921y
```

### 3.5 数据落地过程（前端需要理解的时间差）

```
前端 POST /auth/register
        ↓
后端校验 → scrypt 哈希 → 写入内存 + 落盘 db.json   ← 这一步就是"数据入库"，即成功
        ↓
同步器（每 5 秒）把 db.json 整表重建到 MySQL
        ↓
MySQL 的 users 表出现该用户（含 scrypt 哈希）
```

- **注册接口返回 200 即代表数据已入库**，前端可立即跳转。
- MySQL 里的数据**最多滞后 5 秒**。前端若要立刻从 MySQL 查，需自行等待或直接用接口返回值。
- 同步是**整表重建**语义（DELETE + INSERT），所以 MySQL 表的**自增 id 会重排**，`sms_codes.id` 等不可作为业务主键使用。

## 5. 注意事项清单

| # | 事项 | 说明 |
|---|---|---|
| 1 | **不要直连 MySQL 写数据** | 会被 5 秒同步器覆盖，详见第 0 节 |
| 2 | 端口是 **3307** | 3306 是本机另一个 MariaDB 实例 |
| 3 | 用 `naoshang` 用户 | `root` 无权限连该实例 |
| 4 | 密码从 `.env.local` 读 | `E:\脑商ai\server\mysql\.env.local` |

## 6. 常见问题

**Q：前端能不能直接往 MySQL 插一条测试数据？**
A：不能，会被同步器覆盖。要造数据请走 API 注册，或后端改 db.json。

**Q：为什么我查到的密码是 `scrypt$...` 这种看不懂的串？**
A：这是设计如此——scrypt 加盐哈希，前端不需要处理，登录时后端自动验算。

**Q：注册报 `WEAK_PASSWORD`？**
A：密码需 8-20 位且同时含字母和数字，如 `User12345`。

**Q：注册报"验证码不存在或已过期"？**
A：先调 `/auth/sms/send` 拿验证码；注意 `purpose` 要填 `register`；验证码一次性使用。

**Q：注册报"该手机号已注册"？**
A：手机号唯一，换一个测试号。

**Q：接口返回 404？**
A：检查路径是否误加了 `/api` 前缀。契约层是 `/auth/register`，管理层才是 `/api/xxx`。

**Q：MySQL 里有数据但 API 查不到？**
A：方向反了。API 是真源，MySQL 是镜像——MySQL 有数据说明 API 一定有；API 有数据但 MySQL 查不到，才是同步问题。

**Q：小程序真机调不通？**
A：不能用 127.0.0.1。改用局域网 IP（`192.168.0.44`），手机与电脑同一 WiFi，微信开发者工具勾选"不校验合法域名"。
