# 脑商AI · 部署与运维指南（本机 / 单机正式运行）

> 适用：在本机把「脑商AI 后端 API」跑起来，并把 MySQL 数据库作为可在 IDEA 中可视化的实时镜像。

## 1. 架构说明（重要）

```
   脑商AI 后端 (server.js, 端口 3000)
        │  运行态真源 = data/db.json（内存 + 整份落盘）
        │
        └─► scripts/sync_to_mysql.js --watch
                  每 5 秒检测 db.json 变更，全量镜像到 MySQL
                        │
                        ▼
              MySQL 8.4 (127.0.0.1:3307 / 库 naoshang)
                        │
                        └─► JetBrains IDEA 「Database」面板可视化查看（中文注释）
```

- **db.json 是运行态唯一真源**：所有业务读写都发生在内存与 db.json。
- **MySQL 是可视化镜像**：由同步脚本从 db.json 全量刷新，供查询 / 报表 / IDEA 查看，不参与写路径（避免改库即影响业务）。
- 两者口径由 `scripts/mapping.js` 统一，健康检查的 `--verify` 与同步脚本共用，**不会漂移**。

## 2. 启动

方式一（推荐，双击）：
```
双击  E:\脑商ai\server\start.bat
```

方式二（命令行）：
```
cd E:\脑商ai\server
node scripts/run.js start
```

启动后：
- API： http://localhost:3000  （健康检查 http://localhost:3000/health ）
- 同步：db.json → MySQL 常驻运行

> **托管方式（2026-10-28 变更）**：Windows 下 `run.js` 改用 **Windows 计划任务**托管
> （任务名 `WorkBuddyNaoshangApi` / `WorkBuddyNaoshangSync`），
> 以 SYSTEM 账户运行，**开机自启 + 崩溃自动重启**。
> 原因：原先的 `start /B` 拉起的进程挂在当前会话进程树下，
> 终端 / IDE / 沙箱一结束整棵树被连带回收 → 「显示已启动，几秒后服务就没了」。
> 辅助脚本落地在 `C:\ProgramData\NaoshangAI\taskctl.ps1`（纯 ASCII 路径）。

## 3. 停止

双击 `E:\脑商ai\server\stop.bat`，或命令行 `node scripts/run.js stop`。

停止会同时：停并注销两个计划任务 → 结束对应 node 进程 → 释放 3000 端口。

## 4. 在 IDEA 查看数据库

1. 打开 IDEA 右侧 **Database** 面板，找到数据源 **naoshang (MySQL 8.4)**。
2. 若提示密码，填入数据库密码并保存到 Password Safe。
3. 选中数据源，点右上角 **⟳ 刷新**。
4. 展开后应看到 **30 张表**，每张表带中文表名 / 字段注释（共 45 表结构、418 字段注释；本镜像覆盖 30 张业务表）。

> 仅查看、改数据请在 IDEA 里只读操作；业务数据以 db.json 为准。

## 4.0 同事接入本库（推荐方案，2026-10-28 新增）

完整操作手册见 **`server/colleague-kit/同事接入操作手册.md`**（发给同事即可）。

**给同事的访问入口（浏览器，最省事）**：

```
http://192.168.0.44:7789
```

**给同事的数据库账号（受限，可随时回收）**：

| 项 | 值 |
|----|----|
| 账号 | `colleague` |
| 主机范围 | `192.168.%`（仅局域网，公网连不上） |
| 端口 | `3307` |
| 库 | `naoshang` |
| 密码 | `server/colleague-kit/colleague-credentials.txt` |
| 权限 | `SELECT, INSERT, UPDATE, DELETE, SHOW VIEW` on `naoshang.*` |
| 不给 | `DROP` / `TRUNCATE` / `ALTER` / `CREATE` / `GRANT` / 其它库 |

开通与回收：
```bash
node scripts/colleague_account.js create   # 开通（口令随机生成并落盘）
node scripts/colleague_account.js status   # 查看当前状态与授权
node scripts/colleague_account.js drop     # 一键回收，同事立即无法连入
```

浏览器服务管理（Windows 计划任务托管，SYSTEM 账户 + 开机自启 + 崩溃自动重启）：
```bash
node scripts/run.js viewer start            # 启动（写入模式）
node scripts/run.js viewer start --readonly # 只读模式
node scripts/run.js viewer status
node scripts/run.js viewer stop
```
> 计划任务名 `WorkBuddyNaoshangViewer`，防火墙规则 **Naoshang DB Viewer 7789** 仅放行 LocalSubnet。

### ⚠️ 托管表不可直写（重要）

MySQL 是 `db.json` 的**单向镜像**。同步器 `scripts/sync_to_mysql.js` 在 db.json 变更时
以及**每次进程启动首轮**，对「托管表」执行 `DELETE FROM` + 整表重建：

```
users  orders  quotes  commissions  quota_ledger  quota_transactions
quota_activity_batches  activation_codes  skus  counters  members
regional_agents  co_stores  co_store_owners  allocation_quotes
experience_ledger  columns  payments  coupons  assets  jobs
learning_progress  activity_prices  stock_ledger  promotions_tasks
promotion_tasks  free_upgrade_log  invite_codes  wechat_tickets
sms_codes  password_resets  applications  entitlement_orders
store_transfers  training_feedback  coaches  upline_history  withdrawals
```

**直写这些表的数据会被同步器在秒级抹掉且无法找回。**
浏览器已按同一口径禁写这些表（口径由 `scripts/managed_tables.js` 统一提供，
同步器与浏览器共用，杜绝"界面放行但同步器照样覆盖"的静默丢数据）。

**判定口径必须是「声明式」而非「当前有数据的表」** —— 同步器是常驻进程，
哪怕某表此刻为空，只要之后业务产生了这批数据，它就会被整表重建。
因此托管表集合取自**扫描 `mapping.js` 源码**得到的声明表全集
（`scripts/managed_tables.js` 的 `staticDeclaredTables()`），与数据量完全解耦，
对 db.json 的任何状态都恒定不变。当前口径：**38 张托管表禁写 / 7 张可写**。

可写表（7 张）：`addresses` `app_settings` `material_renders` `pay_accounts`
`settings` `settlements` `support_feedback`

验证脚本：
```bash
node scripts/colleague_capability_test.cjs        # 账号能力边界
node scripts/colleague_write_e2e_test.cjs         # 写入通道 4 层防线
node scripts/colleague_frontend_contract_test.cjs # 前后端契约
node scripts/colleague_persistence_test.cjs        # 写入数据在同步后是否存活
node scripts/colleague_timing_safety_test.cjs      # 时序安全（最关键）
```

## 4.1 同事从另一台电脑连本机 MySQL（局域网）

本机 MySQL 8.4 已按「局域网可访问」配置完毕，同事无需再改库机：

| 项 | 值 |
|----|----|
| 主机地址 | `192.168.0.44`（本机局域网 IP） |
| 端口 | `3307` |
| 账号 | `naoshang` |
| 密码 | 见 `server/mysql/.env.local` |
| 库 | `naoshang` |

已完成的配置：
- `my.ini`：`bind-address=0.0.0.0`、`port=3307`（**不是**只听 127.0.0.1）
- 账号 `naoshang'@'%'`：授权 **库级** `ALL PRIVILEGES ON naoshang.*`（已从 `*.*` 收窄，去掉 SUPER / CREATE USER 等全局权限）
- 账号 `naoshang'@'localhost'`：口令已与 `%` 账号统一（本机脚本走 127.0.0.1，此前因口令不一致全部 1045）
- Windows 防火墙：已加入站规则 **MySQL 8.4 (naoshang) TCP 3307**，仅放行 **LocalSubnet** 段
- 认证插件：`caching_sha2_password`（MySQL 8.4 默认，mysql2 与新版 IDEA 均支持；`mysql_native_password` 在本机已禁用）

同事侧自检：
```bash
mysql -h 192.168.0.44 -P 3307 -u naoshang -p naoshang -e "SELECT 1"
```

**安全提醒**：
- 只在公司局域网内开放，不要把 3307 暴露到公网；
- 灌完测试数据后，可把 `bind-address` 改回 `127.0.0.1` 并 `REVOKE` 远程账号；
- 远程账号权限已收窄到 `naoshang` 库级，但仍建议测试结束后收回。

## 4.2 灌种子数据（ALL_SEED.sql）

全量种子文件：`server/sql/ALL_SEED.sql`（45 张表结构 + 有数据的表数据，由 mysqldump 从本机库导出）。

在**同事那台机器**上导入：
```bash
mysql -h 192.168.0.44 -P 3307 -u naoshang -p naoshang < ALL_SEED.sql
```

> ⚠️ 导入前请确认目标库状态：文件内含 `DROP TABLE IF EXISTS`，会重建表结构。
> 远程账号只对 `naoshang` 库有权限，无法在远程新建其它库（需本机 root 执行）。

## 5. 常用运维命令

| 目的 | 命令 |
|------|------|
| 一次性全量同步 db.json → MySQL | `node scripts/sync_to_mysql.js` |
| 常驻同步（部署时已自动启动） | `node scripts/sync_to_mysql.js --watch` |

## 6. 生产模式注意（如对外网开放）

- 当前默认 `NODE_ENV=local`、`PAYMENT_MODE=sandbox`（模拟支付，下单即成功），**仅适合本机演示**。
- 若设置 `NODE_ENV=production`，**必须**同时设置 `PAYMENT_MODE=live` 并配置真实支付商户号，否则服务会拒绝启动（防「下单即成功」被当成真实收款）。
- 前端 `E:\脑商ai1` 通过 `.env` 中的接口地址连接后端（默认 `http://localhost:3000`）。

## 7. 故障排查

- **API 起不来**：看启动日志里的 `[FATAL]`；常见是 `NODE_ENV=production` 但 `PAYMENT_MODE≠live`。
- **MySQL 连不上**：确认 MySQL8 服务（端口 3307 / 库 naoshang / 用户 naoshang）在运行；密码在 `server/mysql/.env.local`。
- **IDEA 里表为空 / 旧数据**：在后端运行时执行一次 `node scripts/sync_to_mysql.js`，再到 IDEA 点 ⟳ 刷新。
- **想重置 MySQL 镜像**：先 `node scripts/sync_to_mysql.js --backup` 备份，再重跑同步即可。
- **提示「端口 3000 已被占用」**：`node scripts/run.js stop` 会同时注销计划任务并结束进程；若仍占用，用
  `Get-NetTCPConnection -LocalPort 3000 -State Listen` 查 PID 后结束。
- **同步日志报 `Access denied`**：`server/mysql/.env.local` 里的口令与 MySQL 实际口令不一致。
  该文件第一行必须是 `PASSWORD=xxx` 格式（`loadSecret()` 只认**第一个**含 `=` 的非注释行）。
- **同步日志报 `Duplicate entry ... for key 'PRIMARY'`**：db.json 里有主键重复的历史脏数据。
  同步器已做去重（保留最新一条）并打印警告；想彻底清理可重置种子。
- **计划任务相关**：任务名 `WorkBuddyNaoshangApi` / `WorkBuddyNaoshangSync`，
  辅助脚本在 `C:\ProgramData\NaoshangAI\taskctl.ps1`（必须是纯 ASCII 路径，
  否则子 powershell 会静默失败），执行结果写在该目录的 `taskctl.log`。
